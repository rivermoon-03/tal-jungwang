# 탈것:정왕 Design System

## Product context

한국공학대학교 학생이 등하교 교통편을 빠르게 판단하는 모바일 우선 PWA다. 시간표 화면의 핵심 질문은 “학교에서 출발해 목적지까지 어떤 이동 단계가 필요한가”이며, 실제 버스 승차점이 이마트나 시화터미널이면 학교에서 그 승차점까지의 접근 단계를 별도로 보여줘야 한다.

## Visual rules

- 기존 `frontend/DESIGN.md`, `frontend/src/index.css`, `frontend/tailwind.config.js`의 semantic token만 사용한다.
- Pretendard 계열 sans-serif를 유지한다.
- 배경과 카드는 중성 surface 토큰을 사용하고 teal은 실시간 상태, 활성 선택, 핵심 안내에만 제한한다.
- 12px 미만 글꼴을 사용하지 않는다.
- 주요 터치 대상은 최소 44px다.
- 모드/그룹 전환은 기존 슬라이딩 segmented control 문법을 유지한다.
- 버스 노선색은 기존 광역 red, 간선 blue, 시내 cyan 계열을 유지한다.
- 큰 그림자, 대면적 teal, 장식적 gradient, 새로운 색상이나 글꼴을 도입하지 않는다.

## Schedule information hierarchy

1. 상단 모드: 버스 / 지하철 / 셔틀
2. 버스 통학 방향: 하교 / 등교 / 기타 노선
3. 하교 방면: 정왕역 방면 / 시흥시청 방면 / 서울 방면
4. 등교 출발지: 서울 출발 / 시흥시청 출발
5. 한 노선이 여러 방면을 지나면 관련된 각 그룹에 중복 노출한다.
6. 노선 카드: 현재 선택한 방면/출발지 맥락의 목적지와 ETA가 가장 중요하다.
7. 환승 노선은 `학교 → 승차점` 접근 단계와 `승차점 → 선택 방면` 버스 단계를 시각적으로 분리한다.
8. 정적 시간표 노선은 실시간이 없어도 다음 출발 시각과 `시간표` 상태를 목록에 표시한다.
9. 노선 상세는 상단 구간 전환기로 같은 노선의 이용 맥락을 바꿀 수 있지만, 본문에는 선택한 한 구간의 데이터만 표시한다.
10. 시흥시청 실시간과 서울 시간표처럼 데이터 종류가 달라도 한 패널에 합치지 않는다. 구간 전환 시 패널 전체가 해당 구간 데이터로 교체된다.

## Motion and interaction

- 탭 전환은 150~220ms 범위의 기존 `duration-base`/`ease-out`을 사용한다.
- 선택 변경 시 콘텐츠는 짧은 fade-in만 사용한다.
- 눌림 상태와 실제 선택 상태가 일치해야 하며 URL query와 화면 상태를 하나의 변경으로 갱신한다.
