# 버스 승차점 문구 통일 설계

## 목적

버스를 타는 정류장 source의 `출발`·`도착` 문구를 모두 `승차`로 통일한다. 시간표와
실시간의 기술적 차이는 기존 `시간표`·`실시간` 칩이 설명하며, 정류장 제목은 사용자의
행동을 기준으로 표현한다.

## 검토한 접근

1. **DB와 백엔드 역할 기반 정규화 — 채택.** DB 원본 라벨을 보정하고 API 직렬화 시
   `source_role`로 한 번 더 정규화한다. 기존 DB와 신규 seed가 모두 같은 결과를 낸다.
2. **DB만 수정.** 구현은 작지만 migration 누락이나 오래된 데이터가 다시 노출될 수 있다.
3. **프론트에서 문자열 치환.** 화면은 즉시 바뀌지만 API·다른 소비자와 표현이 어긋나며
   `도착`을 유지해야 하는 중간 관측점을 문자열만으로 안전하게 구별하기 어렵다.

## 문구 규칙

| source 역할 | 표시 규칙 | 예시 |
|---|---|---|
| `departure` | 정류장명 + `승차` | `시흥터미널 승차`, `강남역 승차` |
| `boarding_arrival` | 정류장명 + `승차` | `이마트 승차`, `한국공학대학교 승차` |
| `downstream_arrival` | 기존 `도착` 유지 | `시흥시청 도착` |

다음 문구는 이 변경 대상이 아니다.

- 통학 선택 축인 `서울 출발`, `시흥시청 출발`
- 실시간 상태인 `곧 도착`, `도착 정보 없음`
- 버스 이외의 지하철·셔틀 출발/도착 문구

같은 정류장에 시간표와 실시간 source가 함께 있으면 두 행 모두 동일한 `○○ 승차`
제목을 사용하고, 옆의 `시간표`·`실시간` 칩으로 구분한다.

## 데이터와 API

- 신규 프로덕션 보정 SQL은 `bus_information_sources`에서 `departure`와
  `boarding_arrival` 역할의 끝말 `출발` 또는 `도착`을 `승차`로 바꾼다.
- 초기 seed SQL도 동일한 최종 라벨을 사용한다.
- 백엔드 context 직렬화는 source 역할을 기준으로 승차 라벨을 보장한다. 따라서 DB
  migration과 backend 배포 순서가 잠시 어긋나도 사용자는 혼합 문구를 보지 않는다.
- `downstream_arrival` 데이터와 source 역할 자체는 변경하지 않는다.

## 검증

- 서비스 테스트에서 기존 `시흥터미널 출발`, `이마트 도착` 입력이 모두 `승차`로
  직렬화되고 `시흥시청 도착`은 유지되는지 확인한다.
- 시간표 화면 테스트에서 3400, 20-1, 5200, 등교 시간표 source의 라벨을 확인한다.
- 프로덕션 SQL 적용 후 역할별 라벨을 조회하고 실제 브라우저의 서울 방면 목록과
  상세에서 최종 문구를 확인한다.
