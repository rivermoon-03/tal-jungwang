# 통학 버스 시간표 정보 구조 및 탭 전환 수정

작성일: 2026-08-01

## 문제 상황

1. `하교` 목록은 학교에서 출발하는 이동이어야 하지만, 3401처럼 학교→시흥시청과 시흥시청→서울 등 서로 다른 이동 맥락이 한 카드와 한 목록에 섞였다.
2. 시간표의 기본 `버스` 탭에서 `지하철` 또는 `셔틀`을 눌러도 잠시 눌린 뒤 버스 탭으로 돌아왔다.
3. 3400·6502 등교처럼 특정 출발지는 실시간 정류장 데이터가 없고 정적 시간표만 있는데, 목록은 노선 전체의 `is_realtime` 값만 보고 `실시간 도착 정보가 없어요`로 끝났다.
4. 동일 번호가 시흥시청과 서울을 모두 연결하는 경우 한쪽에만 넣거나 한 상세 화면에 두 맥락을 합치면 사용자가 어느 승차점의 정보인지 구분할 수 없었다.

## 원인

### 통학 목적과 물리 노선의 혼용

DB의 `bus_routes.category`는 등교/하교 방향을 구분하지만, 사용자가 선택하려는 출발지·목적지까지 표현하지 않는다. 기존 화면은 이 category와 물리적인 전체 경로 상수만 사용해 통학 구간을 별도로 모델링하지 않았다.

### 탭 URL과 React 상태의 불일치

탭 클릭 시 `history.replaceState()`로 URL만 바꿨다. `replaceState()`는 `popstate`를 발생시키지 않으므로 로컬 query 상태는 이전 `bus`를 유지했고, 렌더 중 URL→mode 동기화가 새 mode를 다시 버스로 덮었다.

### 노선 단위 실시간 여부를 승차점 단위로 오판

`is_realtime=true`이면 시간표 조회 결과를 무조건 무시했다. 하지만 실시간 가능 여부는 노선 번호만이 아니라 선택한 출발지/방면의 GBIS 추적 정류장 유무로 결정해야 한다.

## 해결 방안 및 구현

### 명시적인 통학 맥락 도입

`frontend/src/utils/busCommuteContext.js`에 목록과 상세가 함께 쓰는 맥락을 정의했다.

- 하교: `정왕역 방면`, `시흥시청 방면`, `서울 방면`
- 등교: `서울 출발`, `시흥시청 출발`
- 각 맥락은 노선별 `origin`, `destination`, 화면용 이동 구간, 시간표 `stopId`, 실시간 `realtimeStationId`를 가진다.
- 3401·5602처럼 두 목적지를 모두 잇는 노선은 두 방면에 중복 노출한다. 이는 중복 데이터가 아니라 서로 다른 사용자 선택지다.

목록은 등교/하교 1차 세그먼트 아래에 출발지/방면 2차 세그먼트를 둔다. 기존 디자인 시스템의 `SegmentedControl`, radius와 semantic color token을 재사용했다.

### 실시간 우선, 정적 시간표 폴백

각 카드는 선택한 맥락의 GBIS 정류장이 있고 실제 도착 응답이 있을 때만 `실시간`을 표시한다. 그렇지 않으면 같은 맥락의 `stopId + category`로 정적 시간표를 조회해 다음 출발과 `시간표` 칩을 목록에 바로 표시한다. 따라서 상세를 열지 않아도 3400·6502 등교의 다음 출발을 확인할 수 있다.

### 상세 화면의 맥락 격리

상세에는 해당 노선이 속한 통학 맥락이 둘 이상일 때만 전환 세그먼트를 표시한다. 현재 선택한 맥락의 `stopId`와 `realtimeStationId`만 하위 콘텐츠에 전달한다.

- 시흥시청 맥락이 실시간이면 도착 이력/ETA만 해당 GBIS 정류장 기준으로 표시한다.
- 서울 출발처럼 실시간 정류장이 없으면 해당 출발지의 정적 시간표만 표시한다.
- 다른 출발지·방면 데이터는 동시에 렌더하지 않는다.
- 모바일은 맥락을 잃는 별도 route 페이지 이동 대신 같은 상세 바텀시트를 사용하고, 태블릿/PC는 기존 master-detail 우측 패널을 사용한다.

### 탭 상태 동기화

모드 변경 시 `mode`, query state, 저장 mode, URL을 함께 갱신한다. 이로써 `replaceState()` 이후 이전 query가 새 탭을 되돌리지 않는다.

## 실제 해결 여부

로컬 구현 및 자동 검증 기준으로 해결했다.

- 지하철/셔틀 탭: 클릭 뒤 URL과 `aria-selected`가 함께 유지되는 회귀 테스트 추가
- 방면 분리: 3401·5602의 시흥시청/서울 양쪽 노출 테스트 추가
- 시간표 폴백: 3400·6502 등교가 목록에서 `시간표`를 표시하는 테스트 추가
- 상세 격리: 3401 상세가 현재 방면으로 열리고 상세 안에서 다른 방면으로 전환되는 테스트 추가
- 통학 맥락 유틸 단위 테스트 추가
- 프런트엔드 전체 테스트, 프로덕션 빌드 및 lint를 최종 검증 명령으로 확인

아직 프로덕션 배포는 수행하지 않았다. 따라서 `taljungwang.kr`에서의 최종 해결 여부는 이 변경을 배포한 뒤 실제 모바일·태블릿·PC 브라우저로 다시 확인해야 한다.
